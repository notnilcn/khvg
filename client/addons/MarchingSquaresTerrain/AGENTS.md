# AGENTS.md — MarchingSquaresTerrain (Yūgen's Terrain Authoring Toolkit)

Godot 4.7 editor plugin (v1.2.4, MIT; plugin originally targeted 4.6) for authoring 3D terrain in-editor. **This fork adds hexagonal stepped terrain alongside the original marching-squares vertex-heightmap terrain**: `GridMode` on the terrain node switches between `SQUARES` and `HEXES` (default `HEXES`). In hex mode the world is a pointy-top axial hex grid, each hex owns an integer elevation level, ground/wall texture slots, a grass flag and per-edge transition kinds; chunks are hex-shaped regions that build per-hex fan meshes with vertical cliff walls between levels. Originally made by Yūgen, forked from Jackachulian. Plugin entry point: `plugin.cfg` → `editor/marching_squares_terrain_plugin.gd`. **The plugin ships enabled in this project's `project.godot`.**

## Architecture

### Runtime/algorithm (`algorithm/`, `resources/`, `utils/`)
- `algorithm/terrain/mst_hex_math.gd` — `MSTHexMath` (static, @tool): pointy-top axial hex math ported from the game's `client/Scripts/World/HexMath.cs` and the server's vendored hexx (`to_higher_res`/`to_lower_res` chunk mapping, both external to this repo), plus the 16-slot ↔ vertex-color-pair encoding helpers (`slot_to_color_pair`/`color_pair_to_slot`, consolidated from `MSTDataHandler`).
- `algorithm/terrain/marching_squares_terrain.gd` — `MarchingSquaresTerrain` (`@tool Node3D`), the scene root. `grid_mode` (`SQUARES` = original marching-squares path, `HEXES` = hex stepped terrain, default `HEXES`, switchable in Terrain Settings) selects which mesh path chunks build. Holds the `chunks` dictionary, hex-mode settings (`hex_size` = hex outer radius, `level_height` = Y per elevation level, `chunk_radius` = hexes from chunk center to edge, `default_transition` = derived edge kind for unauthored single-step edges) plus squares-mode `dimensions`/`cell_size`, `blend_mode`, `wall/ridge/ledge_threshold`, 15 terrain textures + 6 grass sprites + albedos/scales, and `StorageMode` (**BAKED** = mesh stored on disk, grass/collision only if `bake_grass`/`bake_collision` are set; **RUNTIME** = rebuild everything from records). Saves chunks on `NOTIFICATION_EDITOR_PRE_SAVE`. On load, chunk node positions are snapped to the position derived from `chunk_coords` (self-heals stale scene-file transforms). `get_hex_global(q, r)` resolves a hex record across chunk borders (default record inside existing chunks, empty = void/missing chunk); `get_elevation_at_world(x, z)` for brush picking. Hex-mode chunks are hex-shaped and hexes have single ownership — neighbors are read across borders via `get_hex_global`, there is no border copying (squares mode still copies `height_map` edges when adding chunks).
- `algorithm/terrain/marching_squares_terrain_chunk.gd` — `MarchingSquaresTerrainChunk` (`@tool MeshInstance3D`), one chunk. In hex mode it stores `hex_data : Dictionary` (local axial `Vector2i` → `{elevation: int, ground: int, wall: int, grass: bool, edges: int}`; `edges` packs 6×2-bit transition kinds in server neighbor-delta order) and builds the whole-chunk mesh via SurfaceTool: per-hex top fans at `elevation * level_height`, vertical cliff walls on edges toward lower/void neighbors (only the higher hex builds the shared wall), and terrace/slope strips for authored or derived transition edges. Transition writes are redirected to the higher hex of the pair by `_get_transition_edge` in the editor plugin. **The editor always rebuilds mesh/grass from records on load — baked mesh/grass are a runtime-only optimization, so stale bakes can never shadow source data.** Vertex channels feed the unmodified shader contract (COLOR/CUSTOM0 = slot pair, CUSTOM1 = grass/ridge/ledge/nearest-wall, CUSTOM2 = packed material blend); in hex mode it pins the shader uniforms `chunk_size = ivec3(2,2,2)`, `cell_size = vec2(1,1)` so UV2 = raw world XZ tiles at 1 world unit (squares mode pins `dimensions`/`cell_size` instead). Collision lives in a `StaticBody3D` child that is freed and recreated on every `regenerate_mesh` and on save — put groups on the chunk node itself, not the body (only group names starting with `navmesh_` are copied over on the save path, see navmesh guide). The live squares-mode mesh path lives in `marching_squares_terrain_cell.gd` + `marching_squares_terrain_vertex_color_helper.gd` (instantiated by `_regenerate_mesh_squares`).
- `algorithm/grass/marching_squares_grass_planter.gd` — `MarchingSquaresGrassPlanter` (`@tool MultiMeshInstance3D`): scatters grass instances inside hex top polygons (seeded rejection sampling, deterministic per hex) at `elevation * level_height`, gated by the per-hex `grass` bool + the slots 1-6 rule. Wind/animation lives at the top of `resources/shaders/mst_grass.gdshader`: the terrain's `animation_fps` export pushes to the shader's `fps` uniform (`fps` 0 = smooth noise wind, >0 = stepped pixel-art motion).
- `resources/mst_data_handler.gd` + `resources/mst_chunk_data.gd` — persistence (hex format: per-chunk `chunk_radius` snapshot + parallel arrays of local axial offsets/elevations/ground/wall/grass/edges). `MSTChunkData` still carries the V1 (color arrays) / V2 (compact arrays) import paths plus embedded→external migration (`needs_migration`/`migrate_to_external_storage`); squares-mode terrains open in `SQUARES` mode. Per-terrain data dir: `[SceneDir]/[SceneName]_TerrainData/[NodeName]_[uid]/chunk_X_Y/metadata.res` (compressed `MSTChunkData`). Only dirty chunks are saved; orphaned chunk/terrain dirs are auto-cleaned on save.
- `resources/mst_json_io.gd` — `MSTJsonIO` (static): versioned JSON export/import (`format: "mst-hex-terrain", version: 1`) using **absolute axial coords** so files are chunking-agnostic and directly consumable server-side. Per-hex defaults are omitted on export; `edges` written as 6 ints in neighbor-delta order when non-default. Files also carry an advisory `texture_slots` + `settings` block.
- `editor/tools/scripts/marching_squares_geometry_baker.gd` + `resources/shaders/mst_terrain_bake*.gdshader` — optional **runtime texture baking** (`enable_runtime_texture_baking`): bakes the multi-texture terrain into per-polygon atlas textures so the game runs a simple baked shader instead of the 15-texture one.
- `utils/marching_squares_thread_pool.gd` — thin WorkerThreadPool group-task wrapper.
- `mc.tct` — legacy/original squares chunk script kept for reference (still declares `class_name MarchingSquaresTerrainChunk`, safe only because the `.tct` extension is not compiled); the live chunk script is the one in `algorithm/terrain/`.

### Editor (`editor/`)
- `marching_squares_terrain_plugin.gd` — `MarchingSquaresTerrainPlugin` (EditorPlugin): input handling (`_forward_3d_gui_input` → `handle_mouse`), brush raycasts, the `TerrainToolMode` enum (BRUSH, LEVEL, SMOOTH, BRIDGE, GRASS_MASK, VERTEX_PAINTING, DEBUG_BRUSH, CHUNK_MANAGEMENT, TERRAIN_SETTINGS, IMPORT_EXPORT), the `draw_pattern()` dispatch, and all undo/redo actions (`draw_*_pattern_action` + `apply_composite_pattern_action`). Brush patterns key hexes as `chunk_coords → local axial Vector2i → sample`; elevations are integer levels, textures are per-hex slots, grass is a per-hex bool. VERTEX_PAINTING's `paint_mode` option also does transition painting (nearest edge to the cursor, owned by the higher hex). New tool behavior is coded here.
- `marching_squares_ui.gd`, `tools/scripts/marching_squares_toolbar.gd`, `marching_squares_tool_attributes.gd` — the dock UI. Attributes are declared as Dictionary entries in `marching_squares_tool_attributes_list.gd` (name/type/label/default; types in the `SettingType` enum in `marching_squares_tool_attributes.gd`) and enabled per-tool via boolean exports in `marching_squares_tool_attribute_settings.gd`.
- `tools/*.tres` — the tools themselves: `MarchingSquaresTool` resources. New tools also need a preload entry in `tools/scripts/marching_squares_toolbox.gd`. `import_export_tool.tres` drives `MSTJsonIO` via two path text fields + two buttons.
- `gizmos/` + `marching_squares_terrain_gizmo_plugin.gd` — editor gizmos (hexagon chunk outlines with neighbor-chunk side culling, hex-prism brush visual, per-hex handles).
- `tools/scripts/marching_squares_texture_*.gd`, `marching_squares_quick_paint.gd` — texture presets (swappable palettes, exported to `resources/texture_presets/`) and quick paints (`resources/quick_paints/`, global ones in `quick_paints/global/`).

## Code style (required — from `code_style_guide.md`)
- `extends` before `class_name`; class names prefixed `MarchingSquares` or `MST` (prefer `MST` for long names).
- snake_case members; private functions get a leading `_` (variables do not).
- **Tabs** in GDScript (the opposite in gdshader files). Two blank lines between functions and after the variable block; `#region` names lowercase.
- Variable typing with a space before the colon: `var foo : float` (functions/dictionaries use normal `:` convention).
- Hidden terrain exports use `@export_custom(PROPERTY_HINT_NONE, "", PROPERTY_USAGE_STORAGE)` with a setter that pushes the value wherever it's needed (e.g. shader param) instead of call chains.
- `##` doc comments only for editor-visible docs; all comments start with a capital.

## Gotchas
- Most scripts are `@tool` and run in the editor — guard editor-only APIs and be careful with scene-tree assumptions at load. Exceptions without `@tool` include the gizmo files, `tool.gd`, `tool_attributes_list.gd`, `tool_attribute_settings.gd`, `texture_names.gd`, `terrain_cell.gd`, `vertex_color_helper.gd`, `engine_wrapper.gd`, and `utils/marching_squares_thread_pool.gd`.
- The terrain shader has an **opt-in cloud-shadow block** (`Effects.Cloud_Shadows` uniform group in `mst_terrain.gdshaderinc`, off by default): when the game's 3dpixelart pipeline is present it pushes the uniforms at runtime via `register_cloud_material` on the shared `terrain_material` and the shader darkens albedo by the sun-projected coverage (albedo-side, not `light()`-side — the toon light caps at 0.3 against sky ambient, so attenuating it alone is barely visible). Keep the uniform names/coverage math in sync with the game addon's `pixelizer_3d/shaders/cloud_fbm.gdshaderinc` when Pixelizer3D is present.
- Vertex "colors" are texture indices, not tint colors: the shader (`resources/shaders/mst_terrain.gdshaderinc`) reads the pair of "on" channels across COLOR/CUSTOM0 as one of 16 slots (0 = rr, 1 = rg, … 15 = aa). Slot 15 (aa) = void (top fan skipped). Only textures 1–6 can have grass. Encode/decode via `MSTHexMath.slot_to_color_pair`/`color_pair_to_slot`.
- In hex mode, elevations are integer levels (`y = elevation * level_height`), stored per hex. Squares mode still uses the original per-vertex heightmap.
- Terrain settings are stored on the `MarchingSquaresTerrain` node via storage-only exports and edited through the plugin's Terrain Settings tool, not the default inspector.
- The plugin UI reads attribute dictionaries top-to-bottom — order in `MarchingSquaresToolAttributesList` defines UI order.
- Brush interactions: SHIFT+LMB keeps drawing, SHIFT+scroll resizes, ALT/RMB deselects (the ALT/RMB/ESC tooltip in `brush_tool.tres`/`hex_terrain_guide.md` notwithstanding, there is no `KEY_ESCAPE` handling in code); CTRL samples (level height / chunk select).
- `MSTHexMath` header references the game's `client/Scripts/World/HexMath.cs` and the server's vendored hexx — both live outside this repo; there is no `client/` or server tree here.
