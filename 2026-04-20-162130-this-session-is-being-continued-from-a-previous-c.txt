  expect:

  Root cause: Godot 4.4.1 C# source generator registers [Export] property
  StringNames as PascalCase ("WeaponScene"), but .tres/.tscn files written by
  GDScript use snake_case (weapon_scene). The name mismatch means the native
  setter is never found, Godot falls back to calling _Set(), and the default
  _Set() does nothing — leaving all exported properties null.

  - ResItem.cs — handles all 17 properties including the special case item_type
  → ItemTypeValue
  - ResPlayer.cs — handles 5 properties including res_weapon → ResWeapon
  - ResEnemy.cs — handles all 9 properties
  - ResDrop.cs — handles 3 properties (subclasses ResDropChest/ResDropFood
  inherit it)
  - Player.cs — handles character_data → CharacterData

  After this fix: WeaponScene will be non-null when an axe/arrow/etc. ResItem is
   loaded, so _InstantiateWeaponNode won't crash. MaxSpeed and MaxHealth will
  also load from the .tres correctly, which should fix WASD movement. The
  ResWeapon on ResPlayer will load, making the starting weapon instantiate
  properly.
